# Vue3 组件通信的六种方式

## 选型速查

| 场景 | 方式 |
|---|---|
| 父传子 | `props` |
| 子传父 | `emits` 事件 |
| 双向绑定 | `v-model`（`modelValue` + `update:modelValue`） |
| 跨层级（祖孙） | `provide` / `inject` |
| 访问子组件方法 | 模板 `ref` + `defineExpose` |
| 全局共享状态 | Pinia |
| 透传原生属性 | `$attrs` |

## 一、props：父传子

```vue
<!-- 子组件 -->
<script setup>
const props = defineProps({
  title: { type: String, required: true },
  list: { type: Array, default: () => [] },   // 对象/数组默认值必须用函数
  size: { type: String, default: 'md', validator: (v) => ['sm', 'md', 'lg'].includes(v) },
})
</script>
```

**props 是单向数据流**：子组件不应该修改 props。Vue 会对对象类型的 props 报警告，但基本类型改了不会有任何提示，只是界面和父组件数据不一致，很难查。

需要"本地可改"时，用 `computed` 派生或 `ref` 拷贝：

```js
const localTitle = ref(props.title)   // 只初始化一次，后续父组件变化不会同步
```

如果希望跟随父组件变化，用 `watch(() => props.title, v => localTitle.value = v)`。

## 二、emits：子传父

```vue
<!-- 子组件 -->
<script setup>
const emit = defineEmits(['change', 'delete'])
emit('change', { id: 1 })
</script>

<!-- 父组件 -->
<Child @change="onChange" @delete="onDelete" />
```

用数组声明时没有校验。需要校验用对象形式：

```js
const emit = defineEmits({
  change: (payload) => payload.id > 0,   // 返回 false 会在开发环境警告
})
```

## 三、v-model：组件双向绑定

Vue3 中组件的 `v-model` 展开为 `:modelValue` + `@update:modelValue`：

```vue
<!-- 子组件 -->
<script setup>
defineProps({ modelValue: String })
const emit = defineEmits(['update:modelValue'])
</script>

<template>
  <input :value="modelValue" @input="emit('update:modelValue', $event.target.value)" />
</template>
```

Vue 3.4 起可以用 `defineModel` 宏简化：

```vue
<script setup>
const model = defineModel()          // 默认对应 modelValue
const title = defineModel('title')   // 具名，父组件用 v-model:title
</script>

<template>
  <input v-model="model" />
</template>
```

一个组件支持多个 `v-model`：

```vue
<MyForm v-model="form" v-model:title="title" v-model:tags="tags" />
```

## 四、provide / inject：跨层级

```js
// 祖先组件
import { provide, ref } from 'vue'
const theme = ref('dark')
provide('theme', theme)
provide('changeTheme', (v) => (theme.value = v))
```

```js
// 任意后代组件
import { inject } from 'vue'
const theme = inject('theme', ref('light'))   // 第二个参数是默认值，强烈建议给
```

三个实践要点：

1. **inject 一定给默认值**，否则组件被单独复用时直接报错
2. 需要响应式就 provide 一个 `ref` 或 `reactive`，provide 普通值不会跟着变
3. 建议用 `Symbol` 作 key，避免命名冲突：

```js
export const ThemeKey = Symbol('theme')
provide(ThemeKey, theme)
```

如果需要后代能修改，更规范的做法是 provide 一个"读 + 写"的对象，而不是直接给 ref 让后代随意改，否则数据流向会变得不可追踪。

## 五、模板 ref + defineExpose

```vue
<!-- 子组件 -->
<script setup>
import { ref } from 'vue'
const count = ref(0)
function reset() {
  count.value = 0
}
defineExpose({ reset, count })   // 不写 expose，父组件拿到的是空对象
</script>
```

```vue
<!-- 父组件 -->
<script setup>
import { ref, onMounted } from 'vue'
const childRef = ref(null)
onMounted(() => childRef.value?.reset())
</script>

<template>
  <Child ref="childRef" />
</template>
```

`<script setup>` 组件默认是封闭的，不加 `defineExpose` 时父组件访问不到任何内部成员。这是有意的设计，避免外部乱改组件内部状态。

## 六、$attrs：属性透传

父组件传了子组件没在 props 里声明的属性，会落到 `$attrs`，默认自动加到根元素上。

```vue
<!-- 包装一个原生 input -->
<script setup>
defineOptions({ inheritAttrs: false })   // 关闭自动透传，手动控制落点
</script>

<template>
  <div class="field">
    <input v-bind="$attrs" />
  </div>
</template>
```

`inheritAttrs: false` 在封装第三方组件时几乎必用，否则 `class`、`placeholder` 会同时落到包装元素上，导致样式错乱。

## 该选哪个

- 只有一层关系，用 props / emits，别上 provide
- 超过两层透传（"props drilling"），用 provide / inject
- 需要调用子组件的方法（打开弹窗、重置表单），用 ref + expose
- 全局状态（用户信息、权限、主题），用 Pinia，不要用 provide 硬扛
