# Vue3 响应式基础：ref 与 reactive

## 一句话区别

`ref` 可以包装任意类型（字符串、数字、对象、数组），`reactive` 只能包装对象类型（对象、数组、Map、Set）。实际项目里优先用 `ref`，需要整体替换对象时不会踩坑。

## ref 的基本用法

```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)
const user = ref({ name: '张三', age: 28 })

function add() {
  count.value++          // 脚本里必须写 .value
  user.value.name = '李四'
}
</script>

<template>
  <!-- 模板里自动解包，不需要 .value -->
  <p>{{ count }} - {{ user.name }}</p>
  <button @click="add">加一</button>
</template>
```

**关键点**：`ref` 在 JavaScript 里是一个带 `.value` 的对象，在模板中 Vue 会自动解包。所以脚本里漏写 `.value` 是最常见的错误，表现是"改了但界面不动"，而且不报错。

容易被忽略的解包例外：

- 在 `reactive` 对象里嵌套的 `ref` 会自动解包
- 数组或 Map 里的 `ref` **不会**自动解包，要写 `arr[0].value`
- `ref` 作为函数参数传递后不会解包

## reactive 的基本用法

```js
import { reactive } from 'vue'

const state = reactive({ count: 0, list: [] })
state.count++                        // 不需要 .value
state.list.push('a')
```

## reactive 的三个致命限制

### 1. 解构会丢失响应性

```js
const state = reactive({ count: 0 })
const { count } = state   // count 只是一个普通数字，后续变化不会触发更新
```

解决方式是用 `toRefs` 或 `toRef`：

```js
import { toRefs } from 'vue'
const { count } = toRefs(state)   // count 是 ref，模板里正常用
```

### 2. 整体替换会断开响应性

```js
let state = reactive({ a: 1 })
state = reactive({ a: 2 })   // 新对象，旧引用上的依赖还挂在老对象上
```

如果确实需要整体替换（比如接口返回后重新赋值），应当用 `ref`：

```js
const state = ref({ a: 1 })
state.value = { a: 2 }       // 正确，ref 会追踪 .value 的替换
```

### 3. 原始类型无法使用

`reactive(0)` 不会报错，但返回的仍是一个普通值，不是响应式对象。数字、字符串、布尔值必须用 `ref`。

## 深层与浅层响应

`ref` 和 `reactive` 默认都是**深层**的：对象内部任意层级的属性变化都会触发更新。这对大对象有性能代价。

如果只需要监听第一层，用浅层版本：

| API | 含义 | 典型场景 |
|---|---|---|
| `shallowRef` | 只有 `.value` 整体替换时触发 | 存大数组、第三方实例、图表对象 |
| `shallowReactive` | 只有第一层属性变化触发 | 顶层配置对象 |

```js
import { shallowRef } from 'vue'
const chart = shallowRef(null)   // ECharts 实例，内部变化不需要响应式
```

## 响应式原理（面试常问）

Vue3 用 **Proxy** 拦截对象的读取与赋值：读取时收集依赖（track），赋值时触发更新（trigger）。

与 Vue2 的 `Object.defineProperty` 相比，Proxy 的优势是：

1. 能监听属性的新增和删除（Vue2 需要 `Vue.set` / `Vue.delete`）
2. 能监听数组索引赋值和 `length` 修改（Vue2 需要重写数组方法）
3. 惰性代理，初始化时不为每个属性递归定义 getter，首屏更快

代价是 Proxy 无法被 polyfill，所以 Vue3 不支持 IE11。

## 选择建议

- 绝大多数情况用 `ref`，心智负担最小
- 一组关联状态用 `reactive` 聚合成对象，但不要解构、不要整体替换
- 存不需要深层响应的重型对象（图表实例、地图实例、大列表）用 `shallowRef`
