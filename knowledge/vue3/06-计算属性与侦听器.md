# Vue3 计算属性与侦听器：computed、watch、watchEffect

## 三者的定位

| API | 作用 | 是否有缓存 | 是否立即执行 |
|---|---|---|---|
| `computed` | 由其他状态派生一个值 | 有 | 首次访问时计算 |
| `watch` | 监听特定源，变化时执行副作用 | 无 | 默认不立即执行 |
| `watchEffect` | 自动收集依赖，执行副作用 | 无 | 立即执行一次 |

判断标准很简单：**要一个值用 computed，要做一件事用 watch / watchEffect**。

## computed

```js
import { ref, computed } from 'vue'

const price = ref(100)
const count = ref(3)

// 只读
const total = computed(() => price.value * count.value)

// 可写
const fullName = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: (v) => {
    const [f, l] = v.split(' ')
    firstName.value = f
    lastName.value = l
  },
})
```

**computed 有缓存**：依赖不变时重复访问不会重新计算。这一点和方法调用有本质区别：

```vue
<!-- 每次重渲染都执行，列表大时明显卡顿 -->
<p>{{ filterList() }}</p>

<!-- 依赖不变就复用结果 -->
<p>{{ filteredList }}</p>
```

三个注意点：

1. **computed 里不能有副作用**（不能发请求、不能改其他状态），只做纯计算
2. **不要用 computed 存异步结果**，它返回的是 Promise 本身，不是一个值。异步派生数据应该用 `watch` + `ref`
3. computed 的返回值在脚本里要写 `.value`，模板里自动解包

## watch

基本用法：

```js
import { watch, ref } from 'vue'

const keyword = ref('')

watch(keyword, (newVal, oldVal) => {
  console.log('变化', oldVal, '→', newVal)
})

// 立即执行一次
watch(keyword, handler, { immediate: true })

// 深度监听
watch(obj, handler, { deep: true })
```

监听多个源：

```js
watch([keyword, page], ([newKw, newPage], [oldKw, oldPage]) => {
  fetchList()
})
```

监听对象的某个属性（推荐写成 getter）：

```js
watch(() => state.count, (v) => console.log(v))
```

监听 reactive 对象：

```js
const state = reactive({ a: 1, b: 2 })
watch(state, () => {})              // 隐式深度监听，改 a 或 b 都会触发
watch(() => state.a, () => {})      // 只监听 a，更省性能
```

**这里有个容易踩的坑**：`watch` 一个 `reactive` 对象时，`newVal` 和 `oldVal` 是同一个引用，所以拿不到旧值。需要旧值时必须监听具体的原始值或 getter。

## watchEffect

```js
watchEffect(() => {
  console.log(keyword.value, page.value)   // 自动收集这两个依赖
})
```

特点：**立即执行一次**，且依赖是运行时自动收集的。适用于"依赖比较多"或"依赖会变化"的场景，比如：

```js
watchEffect(() => {
  // 依赖了 keyword 和 page，两者任一变化都会重新请求
  fetchList(keyword.value, page.value)
})
```

缺点也很明显：**依赖不直观**。如果逻辑里有条件分支，某次执行没走到某个变量，那个变量就不会被收集为依赖，之后它变化也不会触发。这种 bug 极难排查。

所以规范建议：**优先用 `watch` 明确声明依赖**；只有依赖确实很多、且逻辑线性无分支时，才用 `watchEffect`。

## 停止侦听

`watch` 和 `watchEffect` 都返回一个停止函数：

```js
const stop = watch(source, handler)
stop()   // 手动停止
```

在组件内创建的侦听器会随组件卸载自动停止，**不需要手动清理**。但在异步回调或 `setTimeout` 里创建的侦听器不会被自动收集，必须手动停止，否则组件销毁后仍在运行。

## 回调参数与清理

```js
watch(keyword, async (val, old, onCleanup) => {
  const controller = new AbortController()
  onCleanup(() => controller.abort())   // 下一次触发前先取消上一次请求
  const res = await fetch(`/api/search?q=${val}`, { signal: controller.signal })
})
```

`onCleanup` 是搜索框防抖/竞态最实用的工具。不加的话，快速输入时会看到"结果对不上输入内容"——因为先发的请求后返回，把后发的覆盖了。

## 常见的错误组合

**1. 用 watch 去做可以 computed 的事**

```js
// 反模式：多余的响应式依赖
const total = ref(0)
watch([price, count], () => { total.value = price.value * count.value })
```

应改用 `computed`，少一层状态，也不会有"忘记初始化"的问题。

**2. 在 watch 里改被监听的值**

```js
watch(count, (v) => { if (v > 10) count.value = 10 })   // 可能死循环
```

需要截断时加判断条件，或用 computed 的 setter。

**3. 忘记 immediate，导致首屏数据为空**

用 `watch` 做"条件变化就重新请求"时，第一次进入页面不会触发，必须配 `immediate: true` 或单独在 `onMounted` 里调用一次。

**4. 深度监听大对象**

`deep: true` 会递归遍历整个对象。监听上千条数据的列表时，仅遍历开销就很可观。更好的做法是监听具体字段，或者用 `watch(() => list.value.length)` 这类轻量表达式。
