# Vue3 性能优化与常见坑

## 性能优化的六个方向

| 方向 | 手段 | 收益 |
|---|---|---|
| 减少渲染 | `computed` 缓存、`v-memo`、`v-once` | 中 |
| 减少组件体积 | 路由懒加载、异步组件、按需引入 | 高（首屏） |
| 减少响应式开销 | `shallowRef`、`markRaw`、避免深层监听 | 中 |
| 长列表 | 虚拟滚动 | 高 |
| 缓存页面 | `keep-alive` | 中 |
| 打包体积 | 代码分割、Tree Shaking、CDN 外置 | 高 |

## 一、v-memo：跳过子树更新

```vue
<div v-for="item in list" :key="item.id" v-memo="[item.id === selected]">
  <!-- 只有选中状态变化时才重新渲染这一项 -->
</div>
```

`v-memo` 接收一个依赖数组，数组内所有值都没变时，整个子树跳过 diff。适合大列表中"大部分项不变、只有少数项变化"的场景。

数组为空 `v-memo="[]"` 等价于 `v-once`（永不更新）。用错会导致该更新的地方不更新，属于"用了更慢/更容易出 bug"的优化，非必要不用。

## 二、异步组件

```js
import { defineAsyncComponent } from 'vue'

const HeavyChart = defineAsyncComponent(() => import('@/components/HeavyChart.vue'))
```

配加载态与错误态的完整写法：

```js
const HeavyChart = defineAsyncComponent({
  loader: () => import('@/components/HeavyChart.vue'),
  loadingComponent: Loading,
  errorComponent: LoadError,
  delay: 200,        // 200ms 后才显示 loading，避免闪烁
  timeout: 10000,
})
```

弹窗、图表、富文本编辑器这类"点开才用"的组件最适合异步化，能显著减小首屏包体。

## 三、长列表虚拟滚动

DOM 节点超过 1000 个时，滚动会明显卡顿。虚拟滚动只渲染可视区域的几十个节点。

常用库：

- `vue-virtual-scroller`
- `@tanstack/vue-virtual`
- Element Plus 的 `el-table-v2`（内置虚拟化）

判断是否需要：列表超过 500 行，或单行高度较高导致总高度超过 5 万像素。

## 四、避免不必要的响应式

```js
import { shallowRef, markRaw } from 'vue'

// 图表实例不需要深层响应式
const chart = shallowRef(null)

// 冻结的数据源：明确告诉 Vue 不要代理
const rawConfig = markRaw({ series: [...], tooltip: {...} })
```

`markRaw` 用于"永远不会变、也不需要触发更新"的对象（常量配置、第三方实例）。大配置对象不加 `markRaw`，Vue 会为它创建 Proxy，白白消耗内存和访问性能。

## 五、keep-alive 缓存页面

```vue
<router-view v-slot="{ Component }">
  <keep-alive :include="['UserList', 'OrderList']">
    <component :is="Component" />
  </keep-alive>
</router-view>
```

`include` 匹配的是**组件 name**，不是路由 name。用 `<script setup>` 时必须显式 `defineOptions({ name: 'UserList' })`，否则 `include` 不生效——这是非常常见的"缓存没起作用"原因。

## 六、打包优化

```js
// vite.config.js
export default {
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router', 'pinia'],
          element: ['element-plus'],
        },
      },
    },
  },
}
```

把不常变动的依赖单独切包，可以利用浏览器缓存：业务代码更新时，vendor 包的 hash 不变，用户不需要重新下载。

## 十个高频坑

**1. 用 index 作 v-for 的 key**

列表增删后 DOM 复用错位，表现为输入框内容串行、动画错乱。

**2. reactive 对象整体重新赋值**

`state = {...}` 断开响应性。用 `ref` 或 `Object.assign(state, newObj)`。

**3. 解构 reactive / store 丢响应性**

用 `toRefs` / `storeToRefs`。

**4. 在 onMounted 之前访问模板 ref**

`setup` 阶段元素还是 `null`。

**5. 定时器、事件监听不清理**

组件销毁后仍运行，开发环境热更新时请求成倍增长。

**6. 在 watch 回调里改被监听的值**

容易死循环，需要加条件。

**7. computed 里发请求**

computed 应当纯计算，异步数据用 watch。

**8. 直接修改 props**

单向数据流被破坏，对象类型会警告，基本类型静默失效。

**9. keep-alive 的 include 写了路由 name**

必须写组件 name。

**10. 依赖了 v-if 内部的 ref**

`v-if` 为假时元素不存在，ref 为 `null`，需要判空。

## 排查性能问题的顺序

不要一上来就做优化，先定位：

1. **Vue DevTools 的 Performance 面板**：看哪个组件重渲染次数异常
2. **Chrome Performance 录制**：看是 JS 执行、样式计算还是布局耗时
3. **打包分析**（`rollup-plugin-visualizer`）：看包体构成
4. **Network 面板**：首屏资源数量与体积

常见结论是：真正的瓶颈往往不是"Vue 渲染慢"，而是**一次接口返回太多数据**、**没有分页**、**图片未压缩**。先解决这些，再谈组件级优化。
