# Vue3 生命周期钩子

## 完整顺序

一个组件从创建到销毁，钩子的执行顺序是：

```
setup()
  ↓
onBeforeMount
  ↓
（子组件创建与挂载）
  ↓
onMounted
  ↓
（数据变化 → onBeforeUpdate → 重新渲染 → onUpdated，可多轮）
  ↓
onBeforeUnmount
  ↓
（子组件卸载）
  ↓
onUnmounted
```

`<script setup>` 中 `beforeCreate` 和 `created` 不需要写：`setup` 本身就运行在这两个阶段之间，直接写代码即可。

## 常用钩子

```vue
<script setup>
import { onMounted, onUnmounted, onBeforeUpdate, onUpdated } from 'vue'

onMounted(() => {
  // DOM 已挂载，可以访问 ref 指向的元素、初始化图表、发起请求
})

onUnmounted(() => {
  // 清理：定时器、事件监听、WebSocket、第三方实例
})
</script>
```

## 父子组件的挂载顺序

这是最常被问的一点：

- **挂载**：子组件 `onMounted` 先于父组件 `onMounted`
- **卸载**：父组件 `onBeforeUnmount` 先于子组件 `onBeforeUnmount`

原因是父组件必须等子组件挂载完成，自己才算挂载完成。所以父组件在 `onMounted` 里能安全访问子组件暴露的方法（通过模板 ref）。

## 与 keep-alive 配合的两个钩子

```vue
<script setup>
import { onActivated, onDeactivated } from 'vue'

onActivated(() => {
  // 被 keep-alive 缓存的组件重新显示，适合刷新列表数据
})
onDeactivated(() => {
  // 组件被切走但没销毁，暂停轮询、暂停动画
})
</script>
```

注意：被 `keep-alive` 缓存的组件，切走时**不会**触发 `onUnmounted`，只会触发 `onDeactivated`。所以清理逻辑不能只写在 `onUnmounted` 里，否则组件被缓存后定时器一直在跑。

## 错误捕获钩子

```vue
<script setup>
import { onErrorCaptured } from 'vue'

onErrorCaptured((err, instance, info) => {
  console.error('子组件出错', err, info)
  return false   // 返回 false 阻止继续向上冒泡
})
</script>
```

它只能捕获**子组件**抛出的错误，捕获不到自己的异步错误（如 `setTimeout` 里抛的）。全局错误用 `app.config.errorHandler`。

## nextTick：等 DOM 更新完再操作

Vue 的更新是异步批量的。修改数据后，DOM 不会立刻变化，要等下一个微任务。

```vue
<script setup>
import { ref, nextTick } from 'vue'

const list = ref([])
const boxRef = ref(null)

async function add() {
  list.value.push('新项')
  // 此处 DOM 还没更新，boxRef.value.scrollHeight 是旧值
  await nextTick()
  // 现在 DOM 已更新
  boxRef.value.scrollTop = boxRef.value.scrollHeight
}
</script>
```

典型场景：新增一条消息后滚动到底部、输入框自动聚焦、根据新内容的实际高度调整布局。这类"改完数据马上要读 DOM"的需求必须用 `nextTick`，否则拿到的永远是上一次的值。

## 常见错误

**1. 在 setup 顶层直接操作 DOM**

`setup` 执行时组件还没挂载，`ref` 指向的元素是 `null`。所有 DOM 操作放到 `onMounted` 里。

**2. 在 onMounted 里发请求但不处理卸载**

请求返回时组件可能已经销毁，此时赋值不会报错但会泄漏。规范做法是用 `AbortController` 取消，或用一个 `isUnmounted` 标记跳过赋值。

**3. 定时器忘记清理**

```js
let timer
onMounted(() => {
  timer = setInterval(poll, 5000)
})
onUnmounted(() => clearInterval(timer))   // 必须写
```

开发环境热更新频繁，不清理会看到请求成倍增加，很容易误判为后端性能问题。

**4. 在 onUpdated 里改数据**

`onUpdated` 里修改响应式数据可能触发再次更新，形成循环。需要基于 DOM 状态调整数据时，加条件判断或用 `nextTick`。
